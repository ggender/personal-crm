# Личная CRM

Список людей, которых я знаю лично: кто это, откуда знакомы, телефон и почта, заметки о том, о чём договорились.

Что умеет:

- открыть список всех контактов (по алфавиту, с разбивкой по буквам);
- найти человека по имени: регистр и «е/ё» не важны, слова можно писать в любом порядке («петров иван»);
- добавить контакт, в том числе сразу с первой заметкой «О чём договорились»;
- открыть карточку и дописать заметку после разговора: заметки идут от новых к старым, у каждой есть дата;
- изменить контакт (кнопка «Изменить» рядом с именем) или удалить его вместе с заметками (внизу страницы правки, после подтверждения);
- исправить отдельную заметку (значок карандаша у заметки).

Данные хранятся в базе PostgreSQL, а не в браузере. Поэтому в другом браузере по тому же адресу видны те же контакты.

## Что нужно на компьютере

- Node.js 24 и pnpm
- Docker Desktop (в нём работает база данных)

## Первый запуск

```bash
pnpm install        # поставить зависимости
pnpm env:init       # создать файл .env со случайным паролем к базе (пароль на экран не выводится)
pnpm db:setup       # поднять базу в Docker, создать таблицы и заполнить 1000 тестовых контактов
pnpm dev            # запустить приложение
```

Приложение откроется по адресу http://localhost:3000.

## Обычный запуск

1. Запустите Docker Desktop.
2. `pnpm db:up` — поднять базу (если она уже работает, команда ничего не сломает).
3. `pnpm dev` — запустить приложение. Остановить: `Ctrl+C` в терминале.

## Полезные команды

| Команда                       | Что делает                                              |
| ----------------------------- | ------------------------------------------------------- |
| `pnpm db:up` / `pnpm db:down` | запустить / остановить базу (данные сохраняются)        |
| `pnpm db:migrate`             | применить изменения структуры базы                      |
| `pnpm db:seed`                | заполнить тестовыми контактами, только если база пустая |
| `pnpm db:studio`              | открыть просмотрщик базы в браузере                     |
| `pnpm build` и `pnpm start`   | собрать и запустить быструю «боевую» версию (*)         |
| `pnpm typecheck`, `pnpm lint` | проверки кода                                           |

(*) `pnpm start` пишет предупреждение про `output: standalone` — это нормально: такая сборка нужна для сервера, локально всё работает.

## Как устроено

- Next.js (App Router) + TypeScript, интерфейс на React, Tailwind CSS и shadcn/ui.
- База — PostgreSQL 18 в Docker, доступна только с этого компьютера (порт 5433).
- Структура базы описана в `src/db/schema.ts`, миграции лежат в `drizzle/`.
- Браузер к базе не обращается: все запросы делает сервер Next.js (`src/lib/contacts.ts`, `src/app/actions.ts`).
- На компьютере приложение слушает только `localhost`, из сети его не видно. На сервере оно открыто всем (см. ниже).

## Выкатка на сервер

Приложение работает на https://app.vprodcrm.ru. Проверка, что оно живо и какая версия выкачена: https://app.vprodcrm.ru/health — ответ `{"status":"ok","version":"<коммит>"}`.

> Входа нет: любой, кто знает адрес, видит и меняет все контакты. Пока там только тестовые данные — настоящие контакты не вносим, пока доступ не закрыт.

### Как выкатить новую версию

Закоммитить и отправить изменения в ветку `main` (`git push`). Дальше всё само, обычно 3–4 минуты:

1. GitHub Actions собирает образ приложения с тегом — номером коммита — и кладёт его в GitHub Container Registry.
2. Копирует скрипты из `deploy/` на сервер и запускает там `deploy.sh`:
   скачать образ → применить миграции базы (разовый контейнер; упали — новая версия не запускается) → запустить новую версию → проверить `/health` (smoke) → удалить старые образы, кроме текущего и предыдущего.

Ход выкатки — на GitHub во вкладке **Actions → Deploy**: зелёная галочка — версия на сервере, красный крестик — выкатка упала.

### Если выкатка упала

Сама она ничего не откатывает. Посмотреть, что случилось:

```bash
ssh crm
sudo -u deploy /srv/personal-crm/compose.sh ps                 # что запущено
sudo -u deploy /srv/personal-crm/compose.sh logs --tail 100 app # последние логи приложения
```

Откат на предыдущую версию — вручную:

```bash
ssh crm
sudo cat /srv/personal-crm/release.env       # PREVIOUS_IMAGE — предыдущий образ
sudo -u deploy /srv/personal-crm/deploy.sh <значение PREVIOUS_IMAGE>
```

Откат меняет только код: изменения структуры базы, которые успела применить новая версия, остаются.

### Что где лежит

- `Dockerfile` — образ приложения; в нём же скрипт миграций.
- `.github/workflows/deploy.yml` — сборка образа и вызов `deploy/ship.sh`.
- `deploy/` — всё для сервера: `compose.yaml` (приложение и база, проект `prod`), `deploy.sh`, `compose.sh`, `.env.example`, настройка nginx.
- На сервере — папка `/srv/personal-crm` пользователя `deploy` (без sudo, заходит только CI по своему ключу):
  - `compose.yaml`, `deploy.sh`, `compose.sh` — копирует каждая выкатка, руками не править;
  - `.env` — пароль базы, права 600, создаётся один раз руками по `deploy/.env.example`;
  - `release.env` — текущий и предыдущий образ.
- Настройка nginx `deploy/nginx/app.vprodcrm.ru.conf` выкаткой не трогается: если поменяли — поставить на сервер руками.
- В GitHub, окружение `production` (доступно только ветке `main`): секрет `DEPLOY_SSH_KEY` — ключ деплоя; переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS`.
- Логи контейнеров ограничены: до 3 файлов по 10 МБ на контейнер.

### Тестовые данные на сервере

База на сервере один раз заполнена тестовыми данными: 1000 контактов с заметками. Повторить можно только на пустой базе (иначе скрипт ничего не делает):

```bash
git archive HEAD | ssh crm "sudo -u deploy docker run -i --rm --network prod_default --env-file /srv/personal-crm/.env -e COREPACK_ENABLE_DOWNLOAD_PROMPT=0 node:24-alpine sh -euc 'mkdir /src && cd /src && tar -x && corepack enable && pnpm install --frozen-lockfile --reporter=silent && DATABASE_URL=\"postgres://crm:\${POSTGRES_PASSWORD}@db:5432/crm\" pnpm db:seed'"
```
