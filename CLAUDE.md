## Как вносим изменения

### Ветки и PR

- Любое изменение - в своей ветке, имя по сути, без префиксов (`keep-in-touch`); в main только через PR
- «Начинаем фичу / доработку / правку» и `/opsx:propose` - переключись на main, забери изменения, удали локальные ветки, которых уже нет на GitHub; новая ветка от свежего main
- Перед первой правкой файлов проверь ветку: на main - забери изменения и создай новую ветку от свежего main; в рабочей ветке - продолжай в ней; ветка уже влита - новая от свежего main
- «Коммить и пуш» - коммит в текущую ветку, push, PR в main; дай ссылку на PR
- PR открыл - сразу включи автовлитие (`gh pr merge --auto --squash`): вольётся сам после зелёного CI. Не включай, если я сказал вливать позже. Автовлитие недоступно - скажи мне
- После merge - переключись на main, забери изменения, удали ветку локально
- Изменения выкатки (workflows, скрипты в `deploy/`) - тем же путём, через PR

### Правка и фича

- Мелкая правка, в том числе небольшое изменение модели данных - план в режиме планирования, ветка, PR, CI
- Фича - полный цикл: требования → план → реализация по шагам. Инструмент любой, например OpenSpec
- Фича готова, когда выполнены критерии приёмки из её спеки

## Выкатка

### Окружения и сервер

- Окружения: локальное, тест-стенд, прод - у каждого своя база и ключи
- На сервере docker compose, проекты `staging` и `prod` (`-p staging`, `-p prod`)
- База тест-стенда - копия базы прода из последнего бэкапа; испортилась - пересоздаём из свежего бэкапа; письма настоящие, со своим ключом почты; остальные внешние интеграции отключены
- Сервер общий для приложения и лендинга: чужие ключи, папки и настройки nginx на нём не удаляй и не меняй - только добавляй своё; удалить - только с моего согласия
- Логи контейнеров - в журнал сервера (journald): переживают выкатку и откат; размер журнала ограничивает система, старые строки удаляются - диск сервера не забивается
- Логи читаешь сам по ssh, когда прошу; в README - как читать логи

### Как выкатываем

- Скрипты выкатки - в `deploy/` в репо; выкатка копирует на сервер всю папку `deploy/`, новый скрипт уезжает сам; отдельный workflow под скрипты не заводить; в workflow только их вызов
- Один скрипт выкатки и один compose.yaml на тест-стенд и прод, окружение - параметром; бэкап только на проде
- Merge в main → образ с тегом SHA коммита → GHCR → тест-стенд: миграции → новый образ → smoke `/health`
- На тест-стенд и прод едет один и тот же образ; на прод - только SHA, прошедший тест-стенд: Deploy prod проверяет это по истории выкаток тест-стенда в GitHub
- Deploy prod: поле SHA пустое - катит SHA последней зелёной выкатки на тест-стенд; SHA вручную - запасной путь; галочка «откат» - версию прода до текущей, её помнит сервер, без проверки тест-стенда, поле SHA при этом не смотрим; какой SHA выкатился - в итогах запуска
- Прод: бэкап базы → миграции → образ → smoke
- Чистка образов после удачной выкатки на прод: в GHCR храним 10 последних сборок; на сервере удаляем образы старше 2 недель, кроме двух последних версий прода и текущей версии тест-стенда
- После выкатки скажи, как проверить и как откатить

### Сбой и откат

- Красный smoke - выкатка упала, скажи мне. Сам ничего не откатывай, автооткат в скрипты не ставь: откат только вручную, запускаю я
- Откат на прошлую версию прода работает всегда: образы прошлых версий хранятся на сервере
