# Design

## Context

Зачем фича — см. `proposal.md`, раздел Why. Требования — `specs/keep-in-touch/spec.md`. Вид экранов — макет, ссылка в `proposal.md`, раздел Mockups.

Что есть сейчас:

- Таблица `contacts` (имя, о себе, откуда знакомы, телефон, почта, `created_at`, `updated_at`) и таблица `notes` (`contact_id`, `body`, `created_at`). У заметок есть индекс `(contact_id, created_at)`.
- `contacts.updated_at` меняется при правке контакта, при новой заметке и при правке заметки. Поэтому как «последнее общение» он не подходит: правка заметки не должна сбрасывать срок.
- Весь доступ к базе — в `src/lib/contacts.ts`, изменения — серверные действия в `src/app/actions.ts`. Главная (`src/app/page.tsx`) и страница контакта (`src/app/contacts/[id]/page.tsx`) — серверные компоненты, данные читаются при каждом открытии (`connection()`).
- Даты показываются через `Intl` в часовом поясе сервера. На сервере пояс не задан, то есть UTC. Это открытый вопрос из proposal, фича его не трогает.
- База — `postgres:18-alpine` и локально, и на сервере. Тестов в проекте нет, проверка — `pnpm typecheck`, `pnpm lint` и руками в браузере.

## Goals / Non-Goals

**Goals:**

- Одно место, где считается последнее общение, срок и просрочка: и блок на главной, и надпись в карточке берут их из одного SQL-выражения.
- Ошибочное «Пообщались» отменяется без следов, а отмена не затирает более позднее нажатие.
- Миграция только добавляет колонки. Старый образ приложения работает с новой базой, поэтому откат образа не требует отката базы.
- Без новых библиотек.

**Non-Goals:**

- Не меняем показ времени заметок (UTC на сервере) — отдельная правка, см. proposal.
- Не храним историю нажатий «Пообщались» — только последнее.
- Не трогаем `scripts/seed.ts`: частоту в тестовых данных владелец задаёт руками, этого хватает для проверки.

## Decisions

### 1. Две новые колонки у контакта

- `contacts.contact_frequency text NULL` — частота: `weekly`, `monthly`, `quarterly`, `yearly`; `NULL` значит «Не задано». Значения проверяет ограничение `contacts_contact_frequency_check` (`CHECK (contact_frequency IN (...))`), в Drizzle это `check()` в описании таблицы.
- `contacts.last_contacted_at timestamptz NULL` — время последнего нажатия «Пообщались»; `NULL` — не нажимали. «Не задано» его не стирает.

Список значений частоты и русские подписи лежат в новом модуле `src/lib/keep-in-touch.ts` без серверных зависимостей: его используют и схема (`src/db/schema.ts`, относительным импортом — drizzle-kit не понимает алиас `@/`), и клиентские компоненты, и проверка в серверных действиях. Zod-схемы для проверки в серверных действиях — в `src/lib/validation.ts`, рядом с остальными: модуль `keep-in-touch.ts` попадает в браузер, и zod в нём добавил бы на страницы около 85 КБ сжатого кода.

Почему не так:

- Перечисление Postgres (`pgEnum`) для частоты: значение легко добавить, но трудно убрать или переименовать, а откат миграции сложнее. Текст с проверкой даёт ту же защиту от мусора.
- Хранить срок в днях: календарный месяц днями не выражается (28–31 день).
- Отметка как заметка «Связались»: владелец решил, что кнопка заметку не создаёт.
- Отдельная таблица нажатий: история владельцу не нужна, а отмену можно сделать и на одной колонке (решение 4).

### 2. Последнее общение считаем на лету

Последнее общение = `coalesce(greatest(max(notes.created_at), contacts.last_contacted_at), contacts.created_at)`. `greatest` в Postgres пропускает `NULL`, поэтому формула работает, когда нет заметок, нет отметки или нет ни того, ни другого. Отдельную колонку «последнее общение» не заводим.

Почему: такую колонку пришлось бы обновлять при каждой новой заметке и заполнить для старых данных, а при расхождении блок показывал бы неправду. Подсчёт `max` по индексу `(contact_id, created_at)` на личном объёме (тысяча контактов) быстрый. Правка заметки не меняет `notes.created_at`, поэтому требование «правка не сбрасывает срок» выполняется само.

### 3. Срок и просрочка считает база, по Москве

Одно SQL-выражение в `src/lib/contacts.ts`, общее для всех запросов:

- день последнего общения: `(<последнее общение из решения 2> AT TIME ZONE 'Europe/Moscow')::date`;
- срок: `(день последнего общения + интервал)::date`, интервал по частоте — `7 days`, `1 month`, `3 months`, `1 year`;
- сегодня: `(now() AT TIME ZONE 'Europe/Moscow')::date`;
- просрочка в днях: `сегодня − срок`; контакт просрочен, если она больше нуля.

Postgres сам прибавляет календарные месяцы и прижимает к концу месяца (31 января + 1 месяц = 28 февраля), сам знает часовые пояса. Фильтр и сортировка делаются в запросе. Часовой пояс — константа `APP_TIME_ZONE = "Europe/Moscow"` в `src/lib/keep-in-touch.ts`.

Почему не на TypeScript: прибавлять календарные месяцы в заданном часовом поясе на `Date` без библиотеки — много ручного кода и ошибок, а библиотека вроде `date-fns-tz` — новая зависимость.

Функции в `src/lib/contacts.ts`:

- `listOverdueContacts()` — контакты с заданной частотой и просрочкой > 0: `id`, `name`, `frequency`, `overdueDays`. Порядок: `overdueDays` по убыванию, затем имя по `ru-x-icu` (как в общем списке), затем `id`.
- `getContactTouchStatus(contactId)` — для карточки: `frequency`, `dueDate` (строкой `YYYY-MM-DD` через `to_char`, чтобы дата не съехала из-за часового пояса при передаче) и `overdueDays`; при «Не задано» — только `frequency: null`.
- `setContactFrequency(contactId, frequency | null)` — обновляет колонку и `updated_at`, возвращает `false`, если контакта нет (как `updateContact`).
- `markContacted(contactId)` — в одной транзакции читает прежнее `last_contacted_at` (`SELECT … FOR UPDATE`) и ставит `now()`; возвращает `{ previous, marked }` или `null`, если контакта нет. `updated_at` не трогает: отметка — не правка данных контакта.
- `undoContacted(contactId, previous, marked)` — `UPDATE contacts SET last_contacted_at = previous WHERE id = … AND last_contacted_at = marked`; возвращает, нашлась ли строка.

Дату срока в карточке показываем как «14 октября»; если срок не в текущем году — с годом: «7 октября 2027 г.». Новая функция в `src/lib/format.ts` форматирует строку `YYYY-MM-DD` в поясе UTC, чтобы день не сдвинулся.

### 4. Серверные действия и когда обновлять экран

В `src/app/actions.ts`:

- `setContactFrequencyAction(contactId, frequency)` — значение проверяется zod-схемой из `src/lib/validation.ts` и ограничением в базе. После успеха `revalidatePath("/")` и `revalidatePath("/contacts/<id>")`: страница контакта перерисовывается, надпись о сроке обновляется.
- `markContactedAction(contactId)` — возвращает `{ previous, marked }` строками ISO или `{ error }`.
- `undoContactedAction(contactId, previous, marked)` — проверяет zod-схемой, что `marked` — время, а `previous` — время или `null`, и возвращает `{ error? }`. Отмена срабатывает, только если с момента нажатия отметку никто не менял (условие `last_contacted_at = marked`): нажатие в другой вкладке не затрётся.
- Ошибки — «Не удалось сохранить. Попробуйте ещё раз.», для несуществующего контакта — «Контакт не найден».

`markContactedAction` и `undoContactedAction` сами `revalidatePath` не вызывают: иначе главная перерисуется сразу после нажатия, строка пропадёт из блока, и «Отменить» негде будет показать. Экран обновляет клиент через `router.refresh()`:

- на странице контакта — сразу после отметки и сразу после отмены: надпись о сроке меняется, а состояние кнопки «Отмечено · Отменить» сохраняется, потому что клиентский компонент при `refresh` не пересоздаётся;
- в блоке — через 5 секунд после отметки (строка уходит, счётчик уменьшается) или сразу после отмены.

Главная и страница контакта и так читают данные при каждом открытии, поэтому другие страницы обновлять не нужно.

В `addNoteAction` добавляем `revalidatePath("/")`: новая заметка меняет блок на главной.

### 5. Переключатель частоты в карточке — обычные радиокнопки в виде «таблеток»

Клиентский компонент `src/components/contact-frequency-picker.tsx`: группа нативных `<input type="radio">` с подписями «Не задано», «Раз в неделю», «Раз в месяц», «Раз в квартал», «Раз в год». Выбранная подсвечена (тёмная заливка `bg-ink`), на узком экране кнопки переносятся на новую строку. Высота кнопок — 44 px на телефоне, 40 px с ширины `sm`. Выбор сразу виден за счёт `useOptimistic` + `useTransition`; если действие вернуло ошибку, оптимистичное значение само откатывается к прежнему, а сообщение показывается под кнопками (`aria-live`).

Место — новая строка «Как часто общаться» в карточке с данными (`dl` на странице контакта), после «Откуда знакомы» и перед «В контактах с». Строка есть всегда. Под кнопками — надпись о сроке, её рисует сервер:

- срок не прошёл: значок календаря и «Связаться не позже 14 октября» (`text-muted`);
- просрочено: значок часов и «Пора связаться: просрочено на 12 дней» (`text-accent-text`);
- «Не задано»: надписи нет.

Почему не shadcn `ToggleGroup` / `RadioGroup`: пришлось бы добавить новые компоненты, а нативные радиокнопки уже дают управление стрелками с клавиатуры и работу с экранным диктором. Цвета, шрифты и отступы — только токены из `src/styles/tokens.css`.

### 6. Кнопка «Пообщались» — один компонент на два места

Клиентский компонент `src/components/contacted-button.tsx` получает действия отметки и отмены (привязанные к `contactId`) и режим: `card` (страница контакта) или `row` (строка блока). Состояния:

- обычное — кнопка-контур со значком галочки «Пообщались», высота 44 px на телефоне;
- идёт сохранение — кнопка неактивна;
- отмечено — вместо кнопки «Отмечено · Отменить» на 5 секунд; фокус переходит на «Отменить», «Отмечено» объявляется экранному диктору (`aria-live`);
- ошибка — «Не удалось сохранить. Попробуйте ещё раз.», кнопка снова доступна.

На странице контакта кнопка стоит под надписью о сроке в строке «Как часто общаться», с ширины `sm` — в одной строке с надписью, справа. При «Не задано» компонент не рисуется.

### 7. Блок «Пора связаться» на главной

Серверный компонент `src/components/keep-in-touch-section.tsx`, получает готовый список. В `src/app/page.tsx` `listOverdueContacts()` вызывается вместе с `listContacts` и `countContacts` в `Promise.all`, но только когда поиск пуст. Блок рисуется между шапкой (с поиском) и алфавитным списком, если список просроченных не пуст.

Вид по макету: подпись «Пора связаться · 3» в стиле заголовка буквы (`text-label`, `text-accent-text`, заглавные) со значком часов; карточка-список приподнята — рамка `border-line-strong` и тень `shadow-card`, чтобы блок не сливался с группами по буквам. Строка — `<li>` из двух частей рядом, не вложенных друг в друга:

- ссылка на `/contacts/<id>`: аватар, имя, под ним «Раз в месяц · просрочено на 12 дней» (частота `text-muted`, просрочка `text-accent-text`; «день» склоняется через `plural` из `src/lib/format.ts`);
- `ContactedButton` в режиме `row`.

Подписи под именами в новых местах — `text-muted`, а не `text-subtle`: так текст читается контрастнее. Общую часть строки списка (аватар, имя, подпись, ссылка) выносим в небольшой компонент и используем и в блоке, и в общем списке.

### 8. Макет

Макет — холст с экранами для телефона и компьютера, ссылка в `proposal.md` (раздел Mockups). По нему сверяются размеры кнопок (44 / 40 px), значки (часы, календарь, галочка, предупреждение), вид ошибки (светлая подложка `bg-note` со значком и текстом `text-destructive`) и раскладка строки блока. Если макет и требования расходятся, правы требования.

## Risks / Trade-offs

- [Postgres не знает пояс `Europe/Moscow`] → в образе `postgres:18-alpine` база часовых поясов есть; в задачах — проверочный запрос до написания кода.
- [Время заметок на сервере показывается по UTC, а срок считается по Москве: заметка в 01:00 по Москве выглядит вчерашней] → описано в Open Questions proposal, правится отдельно.
- [Нажал «Пообщались» по ошибке] → «Отменить» 5 секунд. Ушёл со страницы раньше — отметка остаётся; поправить можно только заметкой или новой частотой. Принято.
- [Отмена затирает более позднее нажатие из другой вкладки] → отмена срабатывает, только если отметка всё ещё та, что поставили этим нажатием.
- [Отмена принимает от браузера прежнее время] → проверка zod (время или `null`); приложение личное, без входа, подменить можно только свои же данные.
- [Главная перерисуется раньше, чем пройдут 5 секунд, и «Отменить» пропадёт] → действия отметки не вызывают `revalidatePath`, обновление делает клиент по таймеру.
- [Много просроченных — блок длинный и отодвигает список] → владелец выбрал «показывать всех». Если станет мешать, можно добавить «Показать всех» позже без изменения данных.
- [Подсчёт последнего общения на каждое открытие главной] → индекс `(contact_id, created_at)` и фильтр `contact_frequency IS NOT NULL` до объединения с заметками; на личном объёме это миллисекунды.
- [Частоту меняют в двух вкладках одновременно] → сохраняется последнее нажатие, как и с остальными полями.

## Migration Plan

Миграция `drizzle/0001_keep_in_touch.sql` создаётся командой `pnpm db:generate --name keep_in_touch` из изменённой схемы:

```sql
ALTER TABLE "contacts" ADD COLUMN "contact_frequency" text;
ALTER TABLE "contacts" ADD COLUMN "last_contacted_at" timestamp with time zone;
ALTER TABLE "contacts" ADD CONSTRAINT "contacts_contact_frequency_check"
  CHECK ("contacts"."contact_frequency" in ('weekly', 'monthly', 'quarterly', 'yearly'));
```

Что будет с данными: у всех существующих контактов обе колонки пустые — «Не задано» и «Пообщались» не нажимали. Ничего не пересчитывается и не переписывается, блок на главной пуст, пока владелец не задаст частоту. Добавление колонок без значения по умолчанию в Postgres мгновенное, проверка ограничения проходит по тысяче строк за доли секунды.

Выкатка — обычная: merge в main → образ → на сервере разовый контейнер применяет миграцию → стартует новый образ → smoke `/health`. Пока миграция идёт, работает старый образ: он перечисляет колонки по именам и новые не замечает.

Откат (только вручную, запускает владелец):

- Обычный откат — вернуть предыдущий образ. База при этом не откатывается: старый код с новыми колонками работает. При повторной выкатке новой версии миграция уже применена и будет пропущена.
- Убрать колонки совсем (обычно не нужно) — отдельной новой миграцией `ALTER TABLE "contacts" DROP CONSTRAINT "contacts_contact_frequency_check"; ALTER TABLE "contacts" DROP COLUMN "contact_frequency"; ALTER TABLE "contacts" DROP COLUMN "last_contacted_at";`. Выбранные частоты и отметки при этом потеряются, заметки и контакты не пострадают.
