# Proposal

## Why

Приложением хотят пользоваться друзья, а сейчас все видят одни и те же контакты. Больше того, любой, кто знает адрес app.vprodcrm.ru, может читать и менять их. Нужно, чтобы каждый входил под своей почтой, вёл свои контакты и не видел чужих.

## What Changes

- Без входа приложение не открывается: любая страница ведёт на страницу входа. Открытой остаётся только проверка `/health`: по ней выкатка понимает, что приложение живо.
- Вход только по ссылке из письма, паролей нет. На странице входа поле «Почта» и кнопка «Получить ссылку». После отправки — «Ссылка для входа отправлена на <почта>», приходит письмо, ссылка из него открывает приложение. Первый вход и есть регистрация: отдельной формы нет, имя не спрашиваем.
- Почта: пробелы по краям убираются, большие и маленькие буквы не различаются. Неверный адрес — «Проверьте адрес почты» под полем, письмо не уходит. Сервер проверяет почту так же, даже если запрос пришёл не из формы.
- Ответ после отправки одинаковый для старой и новой почты: по нему не понять, есть ли такой пользователь.
- Ссылка работает один раз и 15 минут. Новая ссылка отменяет прежние. Старая или использованная ссылка — страница «Ссылка устарела, запросите новую» с кнопкой на страницу входа.
- Не больше 3 писем на одну почту за 10 минут. Четвёртый запрос — «Слишком часто, попробуйте через несколько минут».
- Вход держится 30 дней с последнего захода на этом устройстве. Можно быть в приложении с нескольких устройств сразу.
- В шапке — почта пользователя и кнопка «Выйти». Выход — только на этом устройстве.
- Письмо: отправитель «Личная CRM» `<noreply@mail.crm.vprodcrm.ru>`, тема «Вход в Личную CRM», кнопка «Войти», что ссылка работает 15 минут, «Если вы не запрашивали вход - просто проигнорируйте письмо».
- Куда уходят письма. На компьютере и в автотестах (в том числе на GitHub) — в почтовую заглушку Mailpit: она работает в Docker рядом с базой, её страница открывается в браузере, войти можно под любым адресом. На сервере — настоящие письма через Resend. Письма везде отправляет Nodemailer, а куда — решает настройка: одна и та же сборка работает и у вас, и на сервере.
- Чьи данные: у каждого контакта и каждой группы есть владелец, заметки принадлежат владельцу контакта. Список, поиск, карточка, заметки, группы, фильтр по группе, блок «Пора связаться» и счётчики показывают только своё. Чужой контакт по прямой ссылке — «Контакт не найден». Запрос к серверу с номером чужой записи ничего не показывает и не меняет.
- **BREAKING** для требований групп: у каждого свои группы, у A и B может быть по группе «Друзья». Названия не повторяются только внутри одного пользователя.
- Новый пользователь видит пустой список — как сейчас: «Пока нет ни одного контакта» и кнопка «Добавить первый контакт». Групп у него нет.
- Всё, что уже есть в базе, становится вашим: на сервере это 1000 тестовых контактов, на компьютере — ваша локальная база. Владелец — пользователь с почтой из настройки `OWNER_EMAIL`. Контактов, заметок и групп после выкатки столько же, сколько до. Демо-данные (`pnpm db:seed`) тоже создаются у вас.
- База: новые таблицы для пользователей, входов на устройствах, ссылок из писем и учёта отправленных писем; у контактов и групп появляется владелец. **Миграция меняет существующие данные**: проставляет владельца всем записям. Покажу её вам до merge.
- **BREAKING** для отката: прошлую версию после этой выкатки можно вернуть только вместе с базой из бэкапа, который сняла эта выкатка. Прошлая версия с новой базой работать не будет.
- Автотесты: каждый сценарий входа — в браузере, письмо берётся из Mailpit; два пользователя A и B — автотест в браузере (критерий успеха из спеки); проверка «только своё» для каждой функции работы с данными — Vitest. Автотест главного сценария из `specs/01-продуктовая-идея.md` остаётся отдельным: перед сценарием он входит под пользователем. В CI рядом с базой для e2e появляется Mailpit.
- Документы: README (как войти на компьютере, что настроить на сервере, как откатить эту выкатку); из «Не делать» в `specs/01-продуктовая-идея.md` и из `openspec/config.yaml` убирается «Вход и регистрация».

Не входит: пароли, вход через Google и соцсети, вход по коду из письма, профиль и смена почты, удаление аккаунта, общий доступ к контактам, приглашения, роли и админка, ограничение запросов по IP.

## Capabilities

### New Capabilities

- `user-auth`: вход по ссылке из письма и выход — страница входа, проверка почты, письмо, одноразовая ссылка на 15 минут, лимит писем, сколько держится вход, почта и «Выйти» в шапке, куда уходят письма.
- `data-ownership`: чьи данные — у каждой записи есть владелец, пользователь видит и меняет только своё, новый пользователь начинает с пустого списка, данные, которые уже есть, достаются владельцу приложения.

### Modified Capabilities

- `contact-groups`: «Группы создаёт владелец» — групп нет у нового пользователя (раньше — «сразу после выкатки фичи групп»); «Названия групп не повторяются» — только среди групп одного пользователя.

`keep-in-touch` не меняется: его правила работают так же, только на контактах пользователя. То, что в блоке «Пора связаться» только свои контакты, записано в `data-ownership`.

## Owner Decisions

Решения владельца — из спеки `specs/02-пользователи-вход.md` и обсуждения:

- Вход — Better Auth, по ссылке из письма (MagicLink). Письма отправляет Nodemailer: на сервере через Resend, на компьютере и в автотестах — в Mailpit.
- Почта владельца, которому достаются существующие данные, — строка `OWNER_EMAIL` в `.env` на сервере и на компьютере. В репозиторий почта не попадает: он на GitHub открыт всем.
- Все тексты — на «вы», как остальное приложение и письмо: «Проверьте адрес почты», «Слишком часто, попробуйте через несколько минут», «Ссылка устарела, запросите новую». Пустой список у нового пользователя — как сейчас: «Пока нет ни одного контакта» и «Добавить первый контакт».
- Ограничение писем — только из спеки: 3 на одну почту за 10 минут. Встроенная в Better Auth защита по IP выключена.
- Автотест главного сценария отдельный от автотестов входа; перед сценарием он входит под пользователем.

## Agent Decisions

Решил агент сам, можно поменять:

1. Отправитель — `noreply@mail.crm.vprodcrm.ru`: «мой домен» из спеки — vprodcrm.ru.
2. Страница входа — `/login`: логотип, заголовок «Вход», поле «Почта», кнопка «Получить ссылку». После отправки форма остаётся с введённой почтой, под кнопкой — «Ссылка для входа отправлена на <почта>»: можно поправить адрес или запросить ссылку ещё раз (это считается в лимит).
3. Почту проверяет только сервер, браузер своих подсказок не показывает: так на экране ровно сообщение из спеки.
4. После входа по ссылке всегда открывается главная, даже если до входа открывали, например, карточку контакта.
5. Вошедший пользователь, открыв страницу входа, попадает на главную.
6. Ссылка выполняет вход в том браузере, где её открыли, — не обязательно в том, где её запросили.
7. В лимит считаются только письма, которые ушли. Сработавший лимит не отменяет ссылки, которые уже пришли: «новая отменяет старые» — только когда новое письмо действительно ушло.
8. Письмо не удалось отправить (сбой почтового сервиса) — «Не удалось отправить письмо. Попробуйте ещё раз.»; прежние ссылки продолжают работать.
9. Страница устаревшей ссылки: «Ссылка устарела, запросите новую» и кнопка «На страницу входа». Тот же текст для любой негодной ссылки: использованной, просроченной, отменённой новой, испорченной.
10. «30 дней с последнего захода» — с точностью до суток: вход продлевается, когда вы открываете приложение, но не чаще раза в сутки.
11. В шапке справа — почта (на телефоне обрезается многоточием) и кнопка «Выйти». На странице входа и странице устаревшей ссылки в шапке только логотип.
12. «Выйти» — без подтверждения, сразу страница входа.
13. Если вход закончился, пока страница открыта, следующее действие откроет страницу входа; несохранённый текст в форме при этом пропадёт.
14. Если база недоступна, действия отвечают «Не удалось сохранить. Попробуйте ещё раз.», как сейчас, — даже когда не удалось проверить вход.
15. Письмо — с кнопкой «Войти» и запасной текстовой версией со ссылкой для почтовых программ без оформления.
16. Ссылки из писем хранятся в базе не сами, а их отпечатком: войти по ним не сможет даже тот, у кого окажется копия базы.
17. Владелец существующих данных создаётся при миграции, только если в базе уже есть контакты или группы. Если данные есть, а `OWNER_EMAIL` не задан или задан неверно, миграция останавливается, база остаётся как была, новая версия не запускается.
18. Номера контактов и групп в адресах остаются числами по порядку. Номер чужого контакта угадать можно, открыть его нельзя: сервер каждый раз проверяет владельца.
19. Пользователя нельзя удалить из базы, пока у него есть контакты или группы: защита на уровне базы. Удаления аккаунта в приложении нет.
20. `pnpm db:seed` работает как раньше — только на базе, где нет ни одного контакта, — и кладёт демо-данные пользователю с почтой `OWNER_EMAIL`, при необходимости создавая его. Групп демо-данные по-прежнему не создают.
21. Mailpit на компьютере — http://localhost:8025. Автотесты пишут на свои одноразовые адреса и чужие письма в Mailpit не трогают.
22. Отправитель, адрес приложения и почтовый сервер — настройки (`MAIL_FROM`, `BETTER_AUTH_URL`, `SMTP_URL`), а не код. Ключ Resend и секрет подписи входа — только в `.env` на сервере.

## Open Questions

Нет. Шаги, которые делаете вы (аккаунт Resend, записи DNS для `mail.crm.vprodcrm.ru`, новые строки в `.env` на сервере и на компьютере), перечислены в `tasks.md`.

## Impact

- База: новые таблицы `users`, `sessions`, `accounts`, `verifications` (их требует Better Auth) и `login_emails` (учёт писем для лимита); колонка `user_id` у `contacts` и `groups`; уникальность названий групп — внутри пользователя. Две миграции: первая только добавляет таблицы входа, вторая проставляет владельца существующим данным.
- Код: новые `src/lib/auth.ts` (Better Auth), `src/lib/mail.ts` (Nodemailer), `src/lib/current-user.ts`, `src/proxy.ts`, `src/app/api/auth/[...all]/route.ts`, страницы `src/app/login/`; шапка в `src/app/layout.tsx`; владелец во всех функциях `src/lib/contacts.ts` и `src/lib/groups.ts`, в `src/app/actions.ts` и на всех страницах; `scripts/migrate.ts`, `scripts/seed.ts`, `scripts/init-env.mjs`, `.env.example`.
- Библиотеки: `better-auth`, `nodemailer` и `@types/nodemailer` — названы в стеке и спеке. Docker: Mailpit — локально в `docker-compose.yml` и в CI.
- Тесты: Vitest — проверки «только своё» и проверка миграции на копии старой базы; существующие тесты получают пользователя. Playwright — сценарии входа и A/B; главный сценарий и «Пора связаться» сначала входят.
- Выкатка: `deploy/compose.yaml` и `deploy/.env.example` — новые настройки. На сервере в `.env` до merge нужны `BETTER_AUTH_SECRET`, `SMTP_URL` (с ключом Resend) и `OWNER_EMAIL`, иначе выкатка остановится ещё до бэкапа. В Resend — домен `mail.crm.vprodcrm.ru` с записями DNS. nginx не меняется.
- После выкатки без входа на app.vprodcrm.ru ничего не видно, кроме `/health`.
