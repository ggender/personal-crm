Вход по ссылке из письма

Каждый входит под своей почтой — без пароля, по ссылке из письма — и видит только свои контакты, заметки и группы. Всё, что уже есть в базе, становится вашим.

1Коротко

  • Без входа приложение не открывается: вместо любой страницы — страница входа.
  • Вход — по ссылке из письма. Ссылка работает один раз и 15 минут. Паролей нет, первый вход и есть регистрация.
  • Вход держится 30 дней с последнего захода на устройстве. В шапке — ваша почта и «Выйти».
  • Каждый видит только своё. Чужой контакт по ссылке — «Контакт не найден». Группы у каждого свои.
  • Существующие контакты, заметки и группы достаются пользователю с почтой из настройки OWNER_EMAIL — то есть вам.
  • На компьютере и в автотестах письма уходят в почтовую заглушку Mailpit (программа, которая принимает письма и показывает их на своей странице, никому не отправляя), на сервере — по настоящему через Resend (сервис рассылки писем).
  • Статус: спроектирована. Ни одна из 28 задач не отмечена. Автотест (программа, которая сама проходит сценарий и сверяет результат) запланирован на каждый из 44 сценариев: 28 про вход, 13 про «чьи данные», 3 новых про группы.

3Как это работает

Без входа — только страница входа

Любая страница приложения без входа ведёт на страницу входа, данных не видно. Открыта только проверка /health: по ней выкатка понимает, что приложение живо.

Одна почта — один пользователь

Пробелы по краям убираются, большие и маленькие буквы не различаются. Первый вход с новой почтой создаёт пользователя — без формы регистрации и без вопроса об имени.

« Anna@Example.COM » и «anna@example.com» — одна почта и одни и те же контакты.
Ссылка: один раз и 15 минут

Ссылка сгорает после первого входа или через 15 минут после письма. Новая ссылка отменяет все прежние ссылки этой почты. Любая негодная ссылка — «Ссылка устарела, запросите новую».

Запросили ссылку в 10:00 и ещё раз в 10:02 → ссылка из первого письма уже не работает, из второго — работает до 10:17.
Не больше 3 писем на одну почту за 10 минут

Четвёртый запрос — «Слишком часто, попробуйте через несколько минут», письмо не уходит. Считаются только письма, которые ушли. Сработавший лимит не отменяет ссылки, которые уже пришли. У каждой почты свой лимит.

Письма в 10:00, 10:03, 10:05 → в 10:06 «Слишком часто», ссылка от 10:05 работает. В 10:11 можно снова: с первого письма прошло больше 10 минут.
Вход держится 30 дней с последнего захода

Каждый раз, когда вы открываете приложение, срок продлевается на 30 дней, но не чаще раза в сутки — поэтому «30 дней» с точностью до суток. Закрытие браузера вход не сбрасывает. Компьютер и телефон — два отдельных входа: «Выйти» на одном не трогает другой.

Заходили 1 октября и не открывали приложение до 5 ноября → на этом устройстве страница входа.
Каждый видит и меняет только своё

У каждого контакта и группы есть владелец — тот, кто их создал. Заметки — владельца контакта. Чужая запись отвечает так же, как несуществующая: «Контакт не найден», «Заметка не найдена», «Группа не найдена». Сервер проверяет владельца при каждом запросе: спрятанная кнопка — не защита.

Номер контакта в адресе угадать можно (они идут по порядку), открыть чужой — нельзя.
Группы у каждого свои

Названия не повторяются только внутри одного пользователя. «Новая группа» на странице контакта ищет совпадение только среди ваших групп.

У Анны есть «Друзья», Борис создаёт «Друзья» → у Бориса своя группа, сообщения о повторе нет.
Всё, что уже есть в базе, — ваше

При выкатке все контакты, заметки и группы получают владельца — пользователя с почтой из OWNER_EMAIL. Ничего не теряется. Демо-данные (pnpm db:seed) тоже создаются у вас. Друг, который войдёт впервые, увидит пустой список.

Куда уходят письма — решают настройки

Письма везде отправляет одна библиотека Nodemailer. На компьютере и в автотестах настройка указывает на Mailpit, на сервере — на Resend. Сборка приложения одна и та же.

Служебные таблицы входа

verifications

Ссылки из писем, пока ими не воспользовались. В базе лежит не сама ссылка, а её отпечаток: по копии базы войти нельзя. Использованная ссылка удаляется.

login_emails

Учёт: когда и на какую почту ушло письмо. По нему считается лимит «не больше 3 писем за 10 минут». Записи старше суток стираются.

accounts

Нужна библиотеке входа Better Auth. Паролей и входа через соцсети нет, поэтому таблица пустая.

Как запрос находит свои данные и не находит чужие

К каждому запросу в базу добавляется условие «и владелец — тот, кто вошёл». Пример: Иван Петров — контакт №15 у Анны. Анна и Борис открывают одну и ту же ссылку /contacts/15.

Вошла Анна

найди контакт №15 у anna@example.com
Нашёлся: карточка Ивана

Вошёл Борис

найди контакт №15 у boris@example.com
Не нашёлся: «Контакт не найден»

Так же работают правка, удаление, заметки, частота, «Пообщались», группы и блок «Пора связаться». Добавить чужой контакт в свою группу или свой — в чужую тоже нельзя.

Миграции: две, применяются вместе

Миграция — скрипт, который меняет устройство базы. Их две, чтобы ту, что меняет ваши данные, было легко прочитать отдельно. При выкатке сначала снимается бэкап (копия базы), потом обе миграции применяются одним целым: ошибка на любом шаге — база остаётся ровно такой, как была, новая версия не запускается.

drizzle/0003_auth.sql не меняет существующие данные
  1. Создаёт новые таблицы: users, sessions, accounts, verifications, login_emails. Старые таблицы не трогает.
drizzle/0004_data_owner.sql меняет существующие данные
  1. Добавляет поле user_id контактам и группам — пока может быть пустым, иначе база не примет старые строки без владельца.
  2. Раздаёт старые данные владельцу: все существующие контакты и группы получают пользователя с почтой из OWNER_EMAIL. Подробно — ниже.
  3. Делает user_id обязательным и меняет правило групп: было «название одно во всём приложении», стало «название одно у владельца».

Этот файл вам покажут до слияния ветки в main.

Как ваши данные получат владельца

Настройка

Строка OWNER_EMAIL=… в .env (файл настроек): на сервере — в /srv/personal-crm/.env, на компьютере — в .env проекта. В репозиторий почта не попадает. Скрипт миграций передаёт её базе.

Миграция спрашивает

В базе есть контакты или группы?

Нет, база пустая

Пользователь не создаётся: владелец появится при первом входе, как любой другой. Так мигрируют тестовые базы и новая установка.

Есть, а почта не задана или неверная

Ошибка. Миграции отменяются целиком, новая версия не стартует, старая продолжает работать.

Есть, почта задана

Создать пользователя с этой почтой и записать его user_id во все контакты и группы.

Что в базе на сервере До выкатки После выкатки
Пользователи таблицы нет 1 — ваша почта
Контакты 1000, владельца нет 1000, владелец — вы
Группы сколько есть, владельца нет столько же, владелец — вы
Заметки сколько есть столько же, не трогались
Кто в какой группе как есть то же, не трогалось

1000 — тестовые контакты, которыми база на сервере заполнена сейчас. Автотест миграции проверяет на копии старой базы, что число контактов, заметок, групп и связей до и после совпадает.

Откат — только вместе и только вручную

Прошлая версия приложения не умеет заполнять user_id и с новой базой не заработает. Откат запускаете вы, в два шага: вернуть прошлую версию приложения (deploy.sh с предыдущим образом) и загрузить бэкап, который сняла эта выкатка (restore.sh). Всё, что внесли после выкатки, — в том числе учётки друзей — при этом пропадёт. Миграции «назад» нет.

6Что агент решил сам

Ваши решения — почта владельца в .env, все тексты на «вы», лимит писем только из спеки — записаны в proposal.md отдельно. Здесь только то, что агент решил без вас.

Продуктовые — стоит просмотреть

  • Отправитель — noreply@mail.crm.vprodcrm.ru: «мой домен» из спеки — vprodcrm.ru.
  • Страница входа: заголовок «Вход»; после отправки форма остаётся с почтой, сообщение — под кнопкой.
  • Почту проверяет только сервер: своих подсказок браузер не показывает.
  • После входа по ссылке — всегда главная, даже если открывали карточку.
  • Вошедший на странице входа попадает на главную.
  • Ссылка выполняет вход в том браузере, где её открыли.
  • В лимит считаются только ушедшие письма; сработавший лимит не отменяет уже пришедшие ссылки.
  • Сбой почты — «Не удалось отправить письмо. Попробуйте ещё раз.», старые ссылки целы.
  • «Ссылка устарела» — один текст на любую негодную ссылку, кнопка «На страницу входа».
  • «30 дней» — с точностью до суток.
  • Шапка: справа почта (на телефоне обрезается) и «Выйти»; на страницах входа — только логотип.
  • «Выйти» без подтверждения.
  • Вход закончился, пока страница открыта, — следующее действие ведёт на вход, несохранённый текст формы пропадёт.
  • База недоступна — как сейчас: «Не удалось сохранить. Попробуйте ещё раз.»
  • Письмо с кнопкой и запасной текстовой версией.
  • pnpm db:seed — только на базе без контактов, кладёт данные вам; групп не создаёт.

Технические — на экраны не влияют

  • Ссылки хранятся отпечатком (хешем — «слепком», по которому саму ссылку не восстановить).
  • Две миграции вместо одной; без OWNER_EMAIL при наличии данных миграция останавливается целиком.
  • Владелец (user_id) — только у контактов и групп; у заметок и «кто в какой группе» он выводится из них.
  • Номера контактов и групп остаются числами по порядку.
  • Пользователя нельзя удалить из базы, пока у него есть данные.
  • Каждая функция работы с данными требует номер пользователя — без него код не соберётся.
  • Быстрая проверка cookie (файла, по которому браузер узнаёт вход) на каждой странице, настоящая — по базе.
  • Продление входа — отдельный короткий запрос при загрузке страницы: страница сама не может обновить cookie.
  • Отправитель, адрес приложения и почтовый сервер — настройки; ключ Resend и секрет входа — только в .env на сервере.
  • Mailpit — в Docker и в CI (проверках на GitHub); автотесты пишут на одноразовые адреса.
  • В быстрых автотестах (Vitest) вход подменён заглушкой; настоящий вход проверяют браузерные (Playwright).
