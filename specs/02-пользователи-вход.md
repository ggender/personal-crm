# Пользователи и вход

## Зачем

> Для кого фича и какую боль решает

Приложением хотят пользоваться друзья. Сейчас все видят одни и те же контакты. Нужно, чтобы каждый заходил под своей почтой и вёл свои контакты, а чужие не видел.

## Главный сценарий

> Основные шаги и критерий успеха - как проверить, что сценарий работает

1. Открыл приложение без входа - вижу страницу входа: поле почты и кнопка «Получить ссылку»
2. Ввёл почту - вижу «Ссылка для входа отправлена на <почта>», письмо приходит
3. Открыл ссылку из письма - я внутри, вижу свои контакты
4. Нажал «Выйти» - снова страница входа

Критерий успеха - два человека, A и B, проверяется автотестом в браузере (e2e):

- A вошёл по ссылке и добавил контакт
- B вошёл по ссылке: контакта A нет ни в списке, ни в поиске; по прямой ссылке на контакт A - «Контакт не найден»

## Вход

- Только по ссылке из письма, паролей нет
- Первый вход и есть регистрация: отдельной формы нет, имя не спрашиваем
- Почта: пробелы по краям убираем, большие и маленькие буквы не различаем
- Неверный адрес почты - ошибка под полем «Проверь адрес почты», письмо не уходит. Сервер проверяет почту так же, даже если запрос пришёл не из формы
- После отправки всегда «Ссылка для входа отправлена на <почта>» - не выдаём, есть ли уже такой пользователь. Исключение - сработал лимит писем, см. ниже
- Ссылка работает один раз и 15 минут. Запросил новую ссылку - старые перестают работать
- Старая или уже использованная ссылка - «Ссылка устарела, запроси новую» и кнопка на страницу входа
- Не больше 3 писем на одну почту за 10 минут. Больше - «Слишком часто, попробуй через несколько минут»
- Вход держится 30 дней с последнего захода на этом устройстве. Можно быть в приложении с нескольких устройств сразу
- В шапке - почта пользователя и кнопка «Выйти». Выход - только на этом устройстве

## Письмо

- Отправитель: «Личная CRM», адрес `noreply@mail.<мой домен>`
- Тема: «Вход в Личную CRM»
- Текст: кнопка «Войти», что ссылка работает 15 минут, «Если вы не запрашивали вход - просто проигнорируйте письмо»

## Куда уходят письма

**На моём компьютере**

- Письма никуда не уходят: попадают в почтовый ящик-заглушку Mailpit. Он работает в Docker рядом с базой, его страница открывается в браузере
- Ссылку входа беру из заглушки
- Войти можно под любым адресом: так проверяю двух пользователей без настоящих ящиков

**В автотестах, в том числе на GitHub**

- Письма попадают в ту же заглушку, автотест берёт ссылку входа оттуда
- Настоящих писем автотесты не шлют

**На сервере**

- Настоящие письма через сервис Resend, ключ - в настройках сервера

**Везде**

- Письма отправляет одна библиотека Nodemailer - и в заглушку, и через Resend
- Куда слать письма - в заглушку или через Resend - решают настройки, не код: одна и та же сборка приложения работает и у меня, и на сервере

## Чьи данные

- У каждого контакта и каждой группы есть владелец. Заметки принадлежат владельцу контакта
- Пользователь видит и меняет только своё: список, поиск, карточка, заметки, группы, фильтр по группе, блок «Пора связаться»
- Чужое не открывается нигде: ни в интерфейсе, ни прямым запросом к серверу с номером чужой записи
- Чужой контакт по прямой ссылке - «Контакт не найден», как будто его нет
- У каждого свои группы: у A и B может быть по группе «Друзья»
- Новый пользователь - пустой список и подсказка «Добавь первый контакт»

## Данные, которые уже есть

- Все контакты, заметки и группы, которые уже есть в базе, становятся моими - их владелец пользователь с моей почтой
- Демо-данные для проверки тоже создаются у пользователя с моей почтой
- Ни одна запись не теряется: контактов, заметок и групп после выкатки столько же, сколько до
- Откат после выкатки входа - только вместе: база из копии, снятой перед выкаткой, и прошлая версия приложения

## Ограничения

> Жёсткие условия, которые агент не выбирает сам

- Вход: Better Auth, вход по ссылке из письма (MagicLink)
- Письма: Resend, отправка - Nodemailer
- Автотест главного сценария из `specs/01-продуктовая-идея.md` остаётся отдельным от автотеста входа. Без входа приложение не открывается, поэтому перед сценарием автотест входит под пользователем
- Права проверяются на сервере: спрятанная кнопка - не защита

## Не делать

> Что сознательно не входит, чтобы агент не додумывал лишнего

Пароли, вход через Google и соцсети, вход по коду из письма, профиль и смена почты, удаление аккаунта, общий доступ к контактам, приглашения, роли и админка

## Открытые вопросы

> Что пока неясно - агент уточнит у вас, а не решит молча

- Откуда приложение берёт мою почту, которой достаются уже существующие данные, - спросить меня при реализации
